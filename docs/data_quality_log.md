# Data-quality log

One row per issue found in the raw data. Nothing gets cleaned, dropped or corrected in the pipeline unless it is in this log with status **agreed**.

**How to add an issue**
1. Give it the next ID (DQ-xx) and fill in every column. Write "?" if you don't know yet.
2. **Evidence** must point to something others can rerun: a notebook and section, or a short code snippet.
3. Leave **Decision** and **Status** empty until the team has discussed it.
4. When the fix is in the code, set the status to **implemented** and name the script.

**Columns**

| Column | What to write |
|---|---|
| ID | DQ-01, DQ-02, ... |
| Signal(s) | Short names from `data/processed/signals.csv` (e.g. `shaft_kw`) |
| Period | From – to (UTC), or "all year" |
| Type | One of: missing / gap · stuck or placeholder value · out of range · sign or unit · drift or bias · duplicate · timestamp · other |
| What we see | One or two sentences, with numbers (how many readings, how big) |
| Evidence | Notebook + section, or a code snippet |
| Readings affected | Count, and % of that signal |
| Impact | What breaks if we ignore it (e.g. "power 20% too low after Jul → looks like fouling") |
| Options | Keep · flag only · set to NaN · correct (how) · drop rows · use other signal |
| Decision | Filled in at the team meeting |
| Status | open · agreed · implemented (script) · rejected |
| Found by / date | Initials, date |

## Notes

**Power fix for DQ-02, DQ-14 and DQ-18 (28 Oct, `prepare_features.py`).** Implemented on branch `fix/scavenge-power` and waiting for team OK. Power after 10 Jul, and wherever the torquemeter reads 0 while the engine turns, now comes from **scavenge air pressure + engine rpm** instead of fuel flow + rpm. Neither the torquemeter nor the fuel meter is involved. Both models are fitted on Jan–Apr and tested on 1 May – 9 Jul (torquemeter trusted), steady rows only:

| Virtual power from | Holdout MAPE | Torquemeter ÷ estimate, Jul–Sep | Oct–Dec |
|---|---|---|---|
| Scavenge pressure + engine rpm (now used) | 1.0 % | 0.81–0.83 | 0.76–0.79 |
| Fuel flow + engine rpm (before) | 5.0 % | 0.76–0.84 | 0.66–0.69 |

- The torquemeter ratio against the scavenge estimate is flat within each period and steps at 10 Jul and mid Oct. That fits a sensor scale fault (DQ-02); fouling can't change power at a given air pressure.
- The fuel-based estimate reads about 16 % above the scavenge estimate from Oct to Dec (median of steady rows), which confirms DQ-18. Fuel-based power was turning that drift into fake fouling: the monthly fouling indicator drops from 50 → 31 % (Oct, ballast), 40 → 23 % (Nov, ballast) and 17 → 3 % (Dec, laden). See `plots4report/fouling_before_after.png`.
- DQ-14 dropouts are now NaN in `power_meas_kw`, and engine rpm replaces shaft rpm there. This adds 1,769 steady rows in the reference period (mostly June).
- Noon-report fuel only partly supports DQ-18: meter ÷ noon fuel is 1.24 in Nov, but 1.08 in Dec and 0.99 in Oct.
- Limitation: the pressure–power relation can drift with turbocharger fouling or air temperature. The flat torquemeter ratio within each period suggests it doesn't here.
